# Regression

**Status:** target state. Covers the tiers every format's tests run in, the corpus of tables from other
engines, how the versions of the reference engines are tracked, and API compatibility. Iceberg's current
suite is described in [regression-suite.md](../../regression-suite.md).

## Tiers, for every format

| Tier | Needs | Iceberg (today) | DuckLake | Delta |
|---|---|---|---|---|
| L0 spec | Nothing | `Spec.Tests` | `DuckLake.Tests` (non-Docker part) | Codecs, log replay over DAT fixtures |
| L0 invariants | Nothing | Validator, model-based, fault injection, corruption | Validator, model-based, corruption; fault injection to add | All four |
| L1 storage and catalog conformance | Emulators | `CatalogConformanceTests` against Glue, REST servers, JDBC | SQLite and PostgreSQL catalogs, run through the same scenarios | S3 put-if-absent, local |
| L1 fidelity | Emulators | `EmulatorFidelityTests` | PostgreSQL behaviours the commit relies on (unique violations, isolation level) | Conditional create on `_delta_log` |
| L1 soak | Emulators | `SoakTests` | Concurrent writers on PostgreSQL | Concurrent writers on S3 |
| L2 cross-engine | Oracles | PyIceberg, Spark, Trino, DuckDB | DuckDB 1.5 and 2.0 | delta-rs, Spark + Delta |
| L3 cloud | AWS | Athena, Glue, S3 | S3 data with a hosted PostgreSQL | S3 |

The same rules apply in every tier: the same binaries run in emulation and AWS, and an unreachable target is
skipped with a reason, or fails under `REQUIRE_TARGET`.

## Corpus from other engines

- **Committed fixtures from every reference writer**, at each version we support, regenerated by the oracle
  scripts in `interop/` and never edited by hand. Iceberg has PyIceberg and Spark fixtures. DuckLake needs
  DuckDB 1.5 and 2.0 lakes committed as fixtures; today it relies on live runs. Delta needs DAT plus
  delta-rs- and Spark-written tables.
- **A pinned test for every bug found**, named after what it guards against. The roadmap's "Bugs these paths
  found" list is the index.
- **Shadow comparison** (`tools/ShadowCompare`) for every format: our reader against the reference reader on
  the same table, compared by order-independent fingerprints. It needs a format-neutral `TableFingerprint`
  in `Lake.TestSupport` and one reader adapter per format.

## Reference engine versions

Each oracle runs against a declared list of versions (for example DuckDB `1.5.5` and `2.0.x`, Spark `4.0.1` +
Iceberg `1.12`). Those versions are pinned in one file (`interop/engines.json`) that the oracle scripts,
`emulation/` and CI all read. The weekly upkeep job also runs against `:latest` and flags any difference.
A known disagreement with an engine is pinned as a characterization test (such as "Trino 478 can't read
DVs"), so the upgrade that fixes it shows up as a test change.

## API compatibility

Each package's public API files and package validation against its own last release are described in
[releases.md](../releases.md), together with how they decide when a package needs a release.

## Done when

- Every format has every tier, or a stated reason it doesn't apply.
- Every format has committed fixtures from every supported reference writer and version.
- Package validation and the API files are in place for every packed project.
