# Int128 and UInt128

[Back to the type matrix](../types.md) · Status: ✗

`new DataField<Int128>(...)` and `DataField<UInt128>` throw `NotSupportedException`.

## Why

Parquet has no 128-bit integer. The INTEGER logical type stops at 64 bits. The candidates:

- **DECIMAL(38, 0)** in a FIXED_LEN_BYTE_ARRAY(16). Every reader understands it, but 38 decimal digits hold up to
  10^38 − 1, while `Int128` goes to about 1.7 × 10^38. The top values would not fit, so the mapping must refuse them.
  `UInt128` goes to 3.4 × 10^38 and needs DECIMAL(39, 0), beyond what most engines read.
- **An unannotated FIXED_LEN_BYTE_ARRAY(16).** Exact, but other readers see bytes.

DuckDB writes `HUGEINT` as a string. Polars writes a file pyarrow cannot read.

## What to use

`decimal`/`BigDecimal` with `DecimalDataField(name, 38, 0)` for values within 38 digits. `BigDecimal` takes the
`BigInteger` directly.

## Proposal

`Int128` ↔ DECIMAL(38, 0), refusing values beyond 38 digits, read back when asked for. Not decided.
